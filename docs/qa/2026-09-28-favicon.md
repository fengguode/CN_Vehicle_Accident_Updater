# QA session: favicon route fix

**Date:** 2026-09-28 (Asia/Shanghai)  
**Scope:** `updater-vnext` web shell and static asset responses.  
**Mode:** Focused disposable-service check using temporary SQLite and port 18788.

## Finding and change

The API server's explicit static allowlist did not contain `/favicon.ico`, and the HTML shell had no icon declaration. Added `apps/web/favicon.svg`, declared `/favicon.svg` in the shell, and routed both `/favicon.svg` and compatibility path `/favicon.ico` to that asset.

- `GET /favicon.ico`: **200**, `image/svg+xml`.
- `GET /favicon.svg`: **200**, `image/svg+xml`.
- `npm test`: **60 passed, 0 failed**.
- The disposable service used a temporary database and port; its process and temporary database files were removed afterward.
- Existing service on port 8788 still returns 404 because it predates the source edit. It was left running; no live service restart or deployment was performed.
- Hermann's independent [live-service recheck](2026-09-28-ui-accept-04-favicon-recheck.md) confirms the pre-fix 404. CUA has no browser surface for visual tab-icon inspection.
