**Scope:** `updater-vnext`, the home-hosted implementation described as the central implementation repository in its README. This is a status and prioritization note, not authorization to change live scheduled tasks or production services.

**Participants:** Xiaofeng (quality/process), Dennis (architecture/review), Yuzhou (product/UI), Torsten (engineering). ## Status

The core hosted alpha is operating: ingestion and authorized social JSONL import feed one SQLite database; the API and paginated UI gate report access by account approval; provenance and unverified-lead state are retained. The README and self-hosting plan report a 294-report/72-vote reconciliation, while the latest UI QA describes 321 local reports. Historical auth, I/O, HTTPS, backup/restore, and forced service/watchdog recovery checks are documented as passing.

Current completion limits:

- The required browser-based User Tester pass for the latest UI is **blocked**. The 2026-09-26 QA record says browser discovery/runtime failed; no actual scenarios or screenshots were produced. Automated tests and API/asset checks passed, but they do not close the visual and interaction gate.
- Physical reboot recovery has not been tested. Deployment docs say daily and backup tasks still require an interactive sign-in.
- `scripts/vnext-daily.mjs` removes its exclusive lock in `finally` only. A forced process termination can leave `data/vnext-daily.lock`, making later runs fail with `EEXIST`. The lock was absent at this review; this is a code-level failure mode, not evidence of a currently stuck run.
- `scripts/install-vnext-tasks.ps1` describes an interactive AtLogOn service task and interactive principals; deployment docs describe an AtStartup, password-backed service and background watchdog. For existing tasks, the installer updates settings only, not trigger, principal, or action. Live task XML and checked-in definitions need reconciliation before relying on those docs.
- The 2026-09-27 daily run succeeded: public updater fetched 14 candidates, inserted 1, found 3 duplicates, rejected 10; social inbox had no records. Its 13 resolved traffic links had 0 page enrichments, median apparent feed-item age 1,145.3 hours and P90 2,110.1 hours, with 278 median content characters. These are index freshness signals, not measured discovery delay. Review several runs before changing cadence or activating another collector.
- Media fields are not part of the reviewed report/import/API contract. The latest UI QA says the 321 examined raw records had no media property names. A media preview feature is therefore not ready for implementation as a display-only change.

## Process friction

The browser runtime was discovered unavailable only when the UI QA gate was due, leaving a finished implementation without required user-flow evidence. Before starting future UI changes, perform a short browser-environment preflight and name the disposable test target. This reduces late QA blockage without weakening the UI acceptance gate.
